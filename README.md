# Novelist — standalone rebuild

A from-scratch Flutter implementation of the **Novelist** novel-writing application, reconstructed
from the shipping Android APK in `Sources_Of_Original/` (decompiled resources, database DDL and the
bundled project templates) rather than from the binary itself.

The goal is behavioural parity with the original — same modules, same data model, same `.nov`
backup format — on a modern, buildable toolchain.

## What it does

* **Library** – many projects ("universes"), each with several books that share the same plot items
  and scene pool. Covers, sorting, duplicate, delete, `.nov` import/export, backup reminders.
* **Plot** – categories (Themes, Events, Characters, Locations, Props, Custom) with configurable
  metadata schemas, statuses, subplots, tags, aliases, notes, pictures, relationships and history.
* **Write** – a project-wide scene pool and a rich-text editor whose documents are byte-compatible
  with the original: paragraph blocks with alignment and inline "mentions" of plot items.
* **Organize** – nested sections per book; scenes are attached, reordered and detached but never
  deleted by the section they belong to.
* **Schedule** – word goals, deadlines, daily progress, streaks and a progress chart.
* **Preview / Export** – one compiler feeds the preview and EPUB 3, ODT and HTML exports, with the
  original's include-sections / include-scenes / table-of-contents switches.
* **Backup** – offline-first: local `.nov` export and restore, no hidden cloud dependency.

## Layout

```
app/                     Flutter application (Android target)
  lib/core/              theme, localisation table, text/typography utilities
  lib/models/            entities mirroring the SQLite schema
  lib/data/db/           schema + thin sqlite3 wrapper (hand-written DAOs, no codegen)
  lib/data/dao/          projects, books, plot, scenes, sections
  lib/data/io/           .nov reader/writer and the EPUB/ODT/HTML compiler
  lib/state/             provider-based controllers
  lib/ui/                library, shell, books, plot, write, schedule, preview, export, backup, settings
  test/                  database-level tests (run on the host VM, no emulator required)
docs/                    data model, architecture, reference analysis, parity checklist, progress
Sources_Of_Original/     the reference APK and its decompiled resources (read-only evidence)
```

## Build

```bash
cd app
flutter pub get
flutter analyze
flutter test          # host needs libsqlite3 (CI installs libsqlite3-dev)
flutter build apk --release
```

CI (`.github/workflows/android-ci.yml`) runs the same steps on every push and publishes the APK as a
build artifact. It also prints the tail of any failing step as a commit comment, so failures are
readable without downloading logs.

Current toolchain: Flutter 3.47 / Dart 3.13, Gradle 8.14.3, AGP 8.11.1, Kotlin 2.2.20, minSdk 24,
compileSdk 36. The Gradle wrapper is generated by CI in an out-of-tree directory because evaluating
the Android project before `local.properties` exists cannot work.

## Known gaps

Localisation is English-only (the original ships 13 locales), cloud send/receive and automatic
backups are not implemented (local backups only), and the biometric app lock is not present. These
are deliberate, documented gaps rather than silent omissions — see `docs/IMPLEMENTATION_PROGRESS.md`.
