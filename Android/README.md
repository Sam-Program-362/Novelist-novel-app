# Novelist for Android

An installable Android app that runs the writing workspace **fully offline**. This folder is a native shell: a single `Activity` hosting the web app from `../public` and `../shared`, which Gradle copies into `assets/` at build time. The result is one APK with no server, no network calls and no account requirement.

The app reads and writes the same `.nov` v4 files as the desktop/web build, so projects move between them by import/export.

## Build

Requirements: JDK 17 and the Android SDK (API 34, build-tools 34.0.0).

```bash
cd Android
echo "sdk.dir=$ANDROID_HOME" > local.properties   # or set ANDROID_HOME
./gradlew assembleDebug
# -> app/build/outputs/apk/debug/app-debug.apk
```

Install it on a device with:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

A prebuilt debug APK is committed at [`dist/novelist-android-debug.apk`](dist/novelist-android-debug.apk).

CI builds the same APK on every push through [`.github/workflows/android.yml`](../.github/workflows/android.yml).

## How it works

| Layer | Role |
| --- | --- |
| `MainActivity.java` | WebView host, `WebViewAssetLoader` (serves the bundle from a stable `https://appassets.androidplatform.net` origin so ES modules load), file chooser, save dialog, confirm dialog, back handling |
| `NovelistNative` bridge | `listCodes`, `readProject`, `writeProject`, `deleteProject`, `saveExport`, `appInfo` |
| `public/native.js` | Detects the bridge and routes the app's existing `/api/*` calls to on-device storage; computes `.nov`, EPUB, ODT, HTML, Markdown and text exports with the shared model; hands downloads to the system save dialog |
| `app/build.gradle` | `syncWebAssets` copies `../public` and `../shared` into the build's asset directory before every build |

Projects live as JSON files in the app's private storage (`files/projects/<code>.json`), written atomically via a temp file. Nothing is sent anywhere. The AI assistant is unavailable in the APK because there is no server to hold the gateway key; the drawer explains this instead of failing.

## Differences from the original Novelist app

This is not the original Flutter binary and does not contain its code. It is a reimplementation built from the reverse-engineered `.nov` format and schema documented in [`../REPORT.md`](../REPORT.md). Practical differences:

- The writing, plot, planning, statistics, revision and export features are implemented; cloud transfer (Google Drive), Easy mode, hyphenation and smart quotes are not.
- Exports (EPUB/ODT) are generated by this project's own templates, so they are not byte-identical to the original app's files.
- The UI is the web workspace rather than Flutter, so it follows the desktop layout with responsive sizing.

## Device check

Run on an Android 14 (API 34) emulator image:

- the debug APK installs with `adb install -r` and `MainActivity` launches, becomes the focused window and draws its themed window;
- the WebView opens `https://appassets.androidplatform.net/index.html` (confirmed through the WebView DevTools socket), so the asset origin and module paths resolve;
- when the system killed the WebView renderer under memory pressure, Chromium aborted the whole app. That is fixed: `onRenderProcessGone` now rebuilds the view and reloads the workspace, and the device log confirmed the handler firing (`renderer gone, crashed=true; reloading`) with the process surviving.

Rendering, the file picker and the save dialog could **not** be exercised there: the emulator had no KVM access, and Chromium's renderers trap under software CPU emulation (`EGL_emulation` reported ~21 s per frame and the system UI itself ANRed). Use a hardware-accelerated device or a KVM-enabled emulator (`./gradlew installDebug` on a connected phone) to check the UI, `ACTION_GET_CONTENT` import and `ACTION_CREATE_DOCUMENT` export end to end.

## Signing

Debug builds are signed with the standard Android debug key so they install directly. For a release build, add your own signing config in `app/build.gradle`; never commit a keystore or its passwords.
